# Группы вкладок, перетаскивание вкладок и восстановление сессии

Дата: 2026-10-06
Статус: утверждён к реализации

## Цель

Полоса вкладок становится вертикальной панелью слева, вкладки раскладываются по
именованным группам, вкладку можно перетаскивать мышью, а при следующем запуске
браузер восстанавливает раскладку групп и вкладок.

Успех считается достигнутым, если: пользователь создаёт группы, даёт им имена и
цвета, перетаскивает вкладки между группами и внутри них, сворачивает группы,
закрывает приложение и после перезапуска видит ту же раскладку.

## Границы

Входит: вертикальная панель групп слева; перетаскивание вкладок и групп;
контекстные меню вкладки и заголовка группы; палитра из 8 цветов; сворачивание
групп; настройка `RestoreSession`; сохранение и восстановление сессии; новые
хоткеи `Ctrl+Shift+N` и `Ctrl+Shift+G`.

Не входит: вертикальные вкладки без групп, вкладки вне групп, несколько окон с
общей сессией, синхронизация, анимации перетаскивания, экспорт/импорт сессии,
иконки сайтов, вертикальные полосы групп в несколько уровней.

## Решения

| Решение | Выбор | Почему |
|---|---|---|
| Раскладка полосы | Вертикальные колонки групп слева | Много групп и вкладок одновременно видно; привычная метрика |
| Хранение вкладок | `TabGroup` владеет `ObservableCollection<Tab>` | Принадлежность вкладки группе — факт, а не соглашение про диапазоны индексов, которое ломается первым же перетаскиванием |
| Архитектура | `TabManager` владеет списком групп; code-behind полосы | Существующий код намеренно «хост + сервисы»; полный MVVM здесь не окупается |
| Логика drop | Вынесена в отдельный чистый класс | Игнорировать UI в тестах — иначе перетаскивание не покрыть тестами вовсе |
| Новые вкладки | В активную группу | Работаешь в группе — вкладки копятся в ней |
| Приоритет URL запуска | Аргументы добавляются к сессии | Ярлык с URL не должен стирать восстановленное |
| Сессия по умолчанию | Восстанавливается (`RestoreSession = true`) | Группы имеют смысл, только если переживают перезапуск |
| Пустая группа | Сохраняется | Заготовка под следующую работу не должна требовать создания группы заново |
| Удаление группы | Закрывает вкладки, затем саму группу | Предсказуемо, как у большинства менеджеров вкладок |
| Перетаскивание | Drag + контекстное меню | В узкой колонке drag не всегда удобен; меню — надёжный запасной путь |
| Тесты | xUnit, логика без WPF | Drag считается чистой функцией, персистентность — через временный файл SQLite |

## Архитектура

```
MainWindow.xaml
 ├─ TabStripView            (строка 0 → уезжает влево, см. ниже)
 ├─ ToolbarView             (строка 1, без изменений)
 ├─ Grid (строка 2)
 │   ├─ col 0: Auto  → TabStripView, MinWidth=150, MaxWidth=420
 │   │              Thumb-ручка на правой кромке — ширина тянется мышью
 │   └─ col 1: *    → ContentHost, DrawerPopup, StatusBar
 └─ StatusBar
```

Тулбар остаётся на всю ширину сверху; переезжает только полоса вкладок — с
горизонтальной строки на левую колонку.

```
TabStripView
 └ DockPanel
     ├─ Top:    кнопка «+ Группа», кнопка «+ Вкладка»
     ├─ Bottom: подсказка пустого состояния
     └─ Center: ScrollViewer(Vertical) → WrapPanel(Horizontal)
         └─ GroupColumn × N     (отдельный UserControl)
             ├─ цветная полоса 3px = цвет группы
             ├─ заголовок: сворачивание · имя · бейдж «N» · ✕
             └─ ItemsControl вкладок (вертикальный StackPanel)
```

Колонки переносятся на следующую строку, когда места не хватает; `WrapPanel`
выравнивает колонки одной строки по верху. Свёрнутая группа сужается до 32 px:
имя пишется вертикально (`RotateTransform`), вкладки скрыты, остаются цветная
полоса и бейдж.

## Модель

### `Models/TabGroup.cs` (новая)

```csharp
public sealed class TabGroup : INotifyPropertyChanged
{
    public Guid Id { get; } = Guid.NewGuid();
    public string Name { get; set; }                 // "Группа 1"
    public int ColorIndex { get; set; }              // 0..7, индекс палитры
    public bool IsCollapsed { get; set; }
    public ObservableCollection<Tab> Tabs { get; }   // состав уведомляет сам
    public int Count => Tabs.Count;
}
```

### `Models/Tab.cs`

Добавляется `Guid GroupId` — только идентификация принадлежности. Контейнером
владеет `TabGroup.Tabs`, поэтому `Tab` не знает, где именно лежит. Остальное
без изменений: `BrowserTabView`, усыпление и заголовок окна не трогаем.

## Сервисы

### `TabManager` — владелец групп

- `List<TabGroup> _groups`; публично `IReadOnlyList<TabGroup> Groups`;
- `Tabs` (плоский, в порядке отображения) пересобирается при любом изменении
  состава групп и служит единственным источником для хоткеев и усыпления;
- `NewTab(string? url, TabGroup? group = null)` — по умолчанию в активную группу;
  если групп нет, создаётся первая «Группа 1»;
- новые операции: `MoveTab(Tab, TabGroup, int index)`, `MoveGroup(TabGroup, int)`,
  `CreateGroup(string? name, int? colorIndex)`, `RenameGroup`, `SetGroupColor`,
  `ToggleGroupCollapsed`, `CloseGroup(TabGroup)`, `RestoreGroups(...)`;
- `CloseTab` больше не удаляет группу: опустевшая группа остаётся;
- `CloseGroup` закрывает вкладки по очереди, затем удаляет группу;
- события: существующий `TabsChanged` шлётся при любом перемещении, новый
  `GroupsChanged` — при создании, переименовании, сворачивании и удалении групп;
  `SessionDirty` — для дебаунс-записи.

### `Services/SessionService.cs` (новая)

`StorageService` дополняется таблицами (то же соединение и та же миграция):

```sql
CREATE TABLE IF NOT EXISTS tab_groups (
    id TEXT PRIMARY KEY, name TEXT NOT NULL,
    color_index INTEGER NOT NULL DEFAULT 0,
    position INTEGER NOT NULL, collapsed INTEGER NOT NULL DEFAULT 0);
CREATE TABLE IF NOT EXISTS session_tabs (
    id TEXT PRIMARY KEY, group_id TEXT NOT NULL,
    position INTEGER NOT NULL, url TEXT NOT NULL,
    title TEXT NOT NULL DEFAULT '', is_active INTEGER NOT NULL DEFAULT 0);
```

`Save(groups, activeTab)` — полная перезапись обеих таблиц в транзакции: сессия
маленькая, диффы не нужны. `Load()` — группы по `position`, вкладки по
`position`, возвращает `(группы, активная вкладка)`. Запись идёт с дебаунсом 2 с
через `DispatcherTimer` окна плюс принудительно в `Window_Closing`. Ошибки БД
глотаются, как и в остальном `StorageService`: недоступное хранилище отключает
сохранение сессии, но не ломает браузер.

## Перетаскивание

Старт — `PreviewMouseLeftButtonDown` на строке вкладки, порог 5 px (иначе это
обычный клик-активация). Далее `DragDrop.DoDragDrop` с источником-объектом `Tab`;
формат — сам `Tab`, дополнительный `DataObject` не нужен.

Цель определяется по позиции курсора:

| Курсор | Действие |
|---|---|
| Над заголовком или свёрнутой колонкой | `MoveTabToGroup` в конец целевой группы |
| Между строками вкладок | Вставка на позицию с подсветкой линии вставки |
| Вне панели | Отмена, вкладка остаётся на месте |

Оба заголовка и свёрнутые колонки подсвечиваются при наведении во время
перетаскивания. Колонки групп перетаскиваются за заголовок (`MoveGroup`).

Решение «куда упало» вынесено в отдельный чистый класс: на входе позиция
курсора, колонки, прямоугольники колонок и строк вкладок; на выходе — цель и
индекс вставки либо признак отмены. `TabStripView` только спрашивает геометрию и
применяет результат. Так перетаскивание тестируется без WPF-окна.

## Контекстные меню

Вкладка: «Переместить в группу» (подменю со списком групп, галочка на текущей) ·
«Создать группу из вкладки» (новая группа с этой вкладкой, имя открыто для
правки) · «Убрать из группы» (в соседнюю группу, при её отсутствии — создаётся)
· «Закрыть вкладку».

Заголовок группы: «Переименовать» · «Сменить цвет» (палитра из 8 цветов) ·
«Свернуть» / «Развернуть» · «Закрыть группу».

## Запуск приложения

`MainWindow.OnContentRendered`:

1. `RestoreSession = true` и `SessionService.Load()` вернули данные — группы и
   вкладки создаются **без единого движка** (`TabManager.RestoreGroups`), активной
   становится сохранённая активная, иначе первая вкладка первой группы. Движки
   создаются лениво при активации, как сейчас.
2. Сессии нет (первый запуск, БД недоступна, данные пустые) — одна «Группа 1» и
   одна вкладка на `HomeUrl`. Это действующее «открыть заданную вкладку».
3. URL'ы из аргументов запуска открываются **после** восстановления, новыми
   вкладками в конце активной группы. Приоритета над сессией не имеют.

`AppSettings.RestoreSession` (по умолчанию `true`) и переключатель в разделе
«Настройки» панели Drawer. При `false` на старте открывается `HomeUrl`, и
сохранённая сессия перезаписывается — это явный выбор пользователя, без
предупреждения.

## Хоткеи

- `Ctrl+Tab` / `Ctrl+Shift+Tab` — сквозной обход плоского списка вкладок по
  порядку групп, с переходом через конец последней группы в начало первой;
  целевая вкладка в свёрнутой группе разворачивает её.
- `Ctrl+T` — новая вкладка в активной группе; свёрнутая активная группа
  разворачивается.
- `Ctrl+W` — закрыть активную вкладку; вкладок в окне не осталось — хост
  закрывает окно, как сейчас.
- `Ctrl+Shift+N` — новая группа с одной вкладкой (`HomeUrl`).
- `Ctrl+Shift+G` — переименовать активную группу.

Новые клавиши проходят через `IBrowserActions`, чтобы горячие клавиши не знали
про `TabManager`.

## Краевые случаи

- Drop вкладки в её же группу на ту же позицию — no-op, без событий.
- Группа закрыта во время перетаскивания её вкладки — перетаскивание
  отменяется, источник проверяет, что вкладка жива.
- Сессия повреждена или БД недоступна — `Load()` возвращает пусто, браузер
  стартует как сейчас; в статус-строке тихо «Сессия не восстановлена».
- Группа без вкладок переживает закрытие всех вкладок и сохраняется пустой.
- `ActiveTab` может находиться в свёрнутой группе: колонка подсвечена, но
  свёрнута; сворачивание не трогает `IsActive`.

## Тесты

Всё ядро вынесено из code-behind, поэтому покрывается xUnit без WPF-окна.

- `TabGroupTests` — `Count`, уведомления при переименовании и сворачивании.
- `TabManagerGroupTests` (fake-хост `Panel`/`IBrowserActions`) — новая вкладка в
  активной группе; `MoveTab` в конец и на позицию; перенос между группами не
  ломает порядок источника; сквозной `Tabs` для хоткеев; закрытие группы не
  трогает соседние; закрытие последней вкладки оставляет группу.
- `TabDropResolverTests` — цель и индекс вставки для всех позиций курсора,
  отмена вне панели, совпадение позиции с текущей (no-op).
- `SessionServiceTests` (временный файл SQLite) — save→load возвращает ту же
  раскладку, цвета, сворачивание и активную вкладку; пустая база даёт пусто;
  повреждённые данные не бросают.
- `StartupPlanTests` — таблица кейсов «сессия есть/нет × `RestoreSession`
  вкл/выкл × URL'ы есть/нет» на чистом классе решения.
- `HotkeysTests` — кейсы `Ctrl+Shift+N` и `Ctrl+Shift+G`.
